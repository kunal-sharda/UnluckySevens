# Unlucky Sevens

Unlucky Sevens is an iMessage-first implementation of standard Catan for 3-4 players.

## Current Status

- the engine is audited, deterministic, and covered by package tests plus deterministic evals
- the repo is in `phase UI hardening`
- the next major step is `phase 10`

## Project Structure

Conceptual source-of-truth layout:

```text
.github/workflows/        # repo CI
App/                      # minimal iOS host app for the Messages extension
MessagesExtension/        # iMessage UI and transcript glue
Packages/
  ULS_CoreGame/           # pure Catan rules engine
  ULS_Transport/          # protocol, envelope, hashing, and payload handling
docs/
  decisions.md            # locked decisions
  product-specs/          # PRD derivatives and product-facing docs
  exec-plans/             # active, completed, and debt-tracking plan artifacts
  quality/                # QA, audits, and golden principles
scripts/                  # generate / clean helpers
ARCHITECTURE.md           # system architecture and protocol model
PLANS.md                  # ExecPlan contract
```

`UnluckySevens.xcodeproj` and `UnluckySevens.xcworkspace` are generated by `./scripts/gen.sh`, may exist locally, and must remain untracked. Tuist manifests are the source of truth.

## Quick Start

```bash
bash ./scripts/gen.sh
open UnluckySevens.xcworkspace
```

Run the `MessagesExtension` scheme, open Messages in Simulator, and launch Unlucky Sevens from the app drawer.

## Test and Eval Commands

```bash
bash ./scripts/gen.sh
swift test --package-path Packages/ULS_CoreGame --skip ULS_CoreGameEvals
swift test --package-path Packages/ULS_CoreGame --filter ULS_CoreGameEvals
swift test --package-path Packages/ULS_Transport
xcodebuild -workspace UnluckySevens.xcworkspace -scheme MessagesExtension -destination 'generic/platform=iOS Simulator' build
```

For simulator smoke steps and manual QA, use [docs/quality/qa.md](docs/quality/qa.md).

## Working In This Repo

Use this source-of-truth order:

1. code, tests, and evals
2. [docs/decisions.md](docs/decisions.md)
3. [ARCHITECTURE.md](ARCHITECTURE.md)
4. the owner docs under `docs/`
5. the PRD, only for product wording or longer-term intent

Hard rules:

- `ULS_CoreGame` stays pure and owns rules, determinism, validation, and secrecy-safe query logic
- `ULS_Transport` stays pure and owns the message/protocol boundary
- `MessagesExtension` consumes engine/query outputs and must not become a second rules engine
- use the product docs in `docs/product-specs/` for scope and flow intent; use `docs/decisions.md` for locked decisions
- do not change protocol fields, validation semantics, or locked decisions without an explicit request
- use [PLANS.md](PLANS.md) for work that is multi-step, risky, spans multiple files, or needs to be resumable without chat memory
