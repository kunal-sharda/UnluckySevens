# Unlucky Sevens

Unlucky Sevens is an iMessage-first, GamePigeon-style implementation of standard Catan for 3-4 players.

## Current Status

- the engine is audited, deterministic, and covered by package-level tests plus deterministic evals
- the repo is currently in `phase UI hardening`
- the next major step is `phase 10`

## Project Structure

Conceptual source-of-truth layout:

```text
.github/workflows/        # repo CI
App/                      # minimal iOS host app for the Messages extension
MessagesExtension/        # iMessage UI and transcript glue
Packages/
  ULS_CoreGame/           # pure Catan rules engine
  ULS_Transport/          # protocol, envelope, hashing, and payload handling
docs/                     # PRD, decisions, audit, tech spec, QA
scripts/                  # generate / clean helpers
Project.swift             # Tuist project manifest
Workspace.swift           # Tuist workspace manifest
Tuist.swift               # Tuist config entrypoint
```

`UnluckySevens.xcodeproj` and `UnluckySevens.xcworkspace` are generated by `./scripts/gen.sh`, may exist locally, and must remain untracked. Tuist manifests are the source of truth.

## Prerequisites

- Xcode 26.2 or compatible local toolchain
- Tuist 4.146.0
- iOS Simulator with Messages available

## Quick Start

```bash
bash ./scripts/gen.sh
open UnluckySevens.xcworkspace
```

If scripts are not executable locally yet:

```bash
chmod +x scripts/*.sh
```

## Run in Simulator

1. Run the `MessagesExtension` scheme, or the host app scheme if needed by your local setup.
2. Open iOS Simulator.
3. Launch Messages and open any conversation.
4. Open the app drawer and select Unlucky Sevens.

## Hello Bubble Smoke Check

1. Run the host app scheme on iPhone Simulator.
2. Open Messages and any thread.
3. Tap `+` and launch Unlucky Sevens.
4. Tap `Send Debug Bubble`.
5. Confirm the transcript bubble shows metadata:
   - Caption: `Unlucky Sevens Debug v1`
   - Subcaption: `debugId: <first 8 chars>`
   - Trailing subcaption: `ts: <unix seconds>`
6. Tap the bubble you just sent.
7. Confirm the extension status text updates:
   - `Send: sent`
   - `Selection: message selected` (or briefly pending)
   - `selectedMessage.url: provided` on ideal path, or `missing` on Simulator fallback path
   - `Payload source: url` or `summaryText`
   - `Decode: Decoded: type=debug, v=1, ...`
8. Repeat twice and confirm `debugId` and timestamp change each send.
9. Simulator caveat: message selection can lag; the extension retries for about 1.2 seconds before settling.

## Test and Eval Commands

```bash
bash ./scripts/gen.sh
swift test --package-path Packages/ULS_CoreGame --skip ULS_CoreGameEvals
swift test --package-path Packages/ULS_CoreGame --filter ULS_CoreGameEvals
swift test --package-path Packages/ULS_Transport
xcodebuild -workspace UnluckySevens.xcworkspace -scheme MessagesExtension -destination 'generic/platform=iOS Simulator' build
```

- `ULS_CoreGameTests` is the normal deterministic core test suite.
- `ULS_CoreGameEvals` is the deterministic engine eval harness for long-running scripted full-match scenarios.
- `ULS_TransportTests` covers transport roundtrips, decode failures, and payload budgets.

## Architecture Overview

- `MessagesExtension` handles iMessage-specific UI, transcript interaction, and local debug-driver behavior.
- `ULS_CoreGame` contains the pure rules engine, deterministic state transitions, and validation.
- `ULS_Transport` contains the `STATE`/`INTENT` envelope layer, payload codecs, hashing helpers, and size checks.

## STATE vs INTENT

- `STATE` bubbles are authoritative snapshots of the game and must validate against the prior canonical state.
- `INTENT` bubbles are anchored requests against a base state and do nothing unless the current player incorporates them into a later `STATE`.
- This separation is the core async authority model for the iMessage game.
